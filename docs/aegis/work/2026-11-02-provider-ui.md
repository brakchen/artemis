# 模型配置与 Provider 表单样式修复

## 范围与原因

用户反馈模型配置、Provider 设置与 Artemis 原有界面不一致。以 HP 上实际运行的页面为参照，沿用现有蓝色主色、卡片边框、字体、36px 表单控件和圆角规范。

复现确认：协议与厂商选择框仍使用浏览器默认外观；新增 fieldset 没有纵向布局与行间距；独立的说明段落未命中嵌套样式，回落到 16px 正文字号；Provider 列表的编辑、删除按钮也未命中输入框内部的图标按钮样式。

## Changelog — 2026-11-02

- 统一协议、厂商下拉框的高度、字体、边框、圆角、箭头、焦点与禁用状态，保留原生 select 的键盘操作。
- 恢复表单内 12px 行间距，重置 fieldset 默认 margin，统一辅助说明的字号、颜色与行高。
- 将保存按钮放在选项之后的操作栏；清除密钥使用现有危险操作色；窄窗口下操作按钮等宽纵向排列。
- 将目录校验、默认服务的说明放回对应复选框内，支持完整换行并关联 aria-describedby。
- 为图标操作补充可访问名称与键盘焦点；编辑态显示明确的编辑标题。
- 统一 Provider 列表按钮与模型摘要布局，支持长模型 ID、配置路径和窄窗口换行。
- 将 MiniMax 迁移命令收纳为与现有界面一致的提示卡片；模型选择器的 Picking 文案复用已有翻译。

仅修改首页模板和样式。原有 API、密钥保存、默认提供商解析、校验与跳过校验、清除确认逻辑均沿用既有实现。

## 验证

- 完整 Python 单元测试：3394 passed、8 skipped；将 PytestUnhandledThreadExceptionWarning 视为错误执行。其余 89 条为依赖弃用或既有 mock 警告。
- 完整 Angular 测试：145 SUCCESS，包含 Provider 新建、编辑、失败重试、跳过目录校验、清除确认和取消编辑。
- 生产构建：`npm run build` 成功。首次直连 Google Fonts 失败，使用本机已有 HTTPS 代理后构建成功；没有修改产品的字体或构建配置。
- Chrome 页面核对：1440×1000 桌面及 375×1000 窄窗口，覆盖中英文、新建和编辑状态。
- 窄窗口 Provider 表单横向溢出为 0；147 字符模型 ID 不造成溢出；操作栏三个按钮与可用宽度一致。
- 实际键盘操作：Tab 可进入协议选择框，Home/Enter 可选择 OpenAI；空格可切换目录校验复选框，保存按钮文案随之更新。
- 编辑时密钥输入保持空白，名称保持只读；取消编辑后草稿复位。浏览器核对没有提交真实 Provider 写入、调用模型或操作设备。

截图与浏览器检查结果保存在本任务工作树的 `scratch/provider-ui/`，属于本地审阅产物，不入库。

## 发布约定

本次只有前端模板与样式变更。HP 发布时保留现有模型配置、凭据及未跟踪文件，在独立目录生成生产构建，先发布带哈希的静态资源，再原子替换 index.html，并保留旧资源。发布后核对实际服务返回的 bundle 与构建产物哈希，避免仅凭 Git 更新判断页面已更新。
